Chapter 2 · LLM Fundamentals

Pre-training turns trillions of tokens into a base model

One task, predict the next token, run over a large slice of the internet on thousands of GPUs. That run sets almost all of a model's knowledge and its compute bill.

8 sections · needs: Chapter 1 (a GPT-2 forward pass), logs and exponents · code uses only the Python standard library

01Overview

Pretraining runs one task, at a cost of 6ND FLOPs

A base model is one checkpoint of weights. Given any prefix, it returns a probability distribution over the next token. Three numbers describe how it was made.

Check the 405B bar: 6 × 4.05e11 × 1.56e13 ≈ 3.8e25 FLOPs. At 40% of peak that is about 26 million GPU-hours, which is why it ran on 16,384 GPUs for months.

train_cost.py
# Back-of-envelope cost of a pretraining run.
# Why: before any code is written, this arithmetic decides whether a run is feasible.

def train_cost(params, tokens, gpus, peak_flops=989e12, mfu=0.40, usd_per_gpu_hour=2.5):
    flops = 6 * params * tokens
    seconds = flops / (gpus * peak_flops * mfu)
    gpu_hours = gpus * seconds / 3600
    return flops, seconds / 86400, gpu_hours, gpu_hours * usd_per_gpu_hour

for name, n, d, g in [
    ("GPT-2 124M, 10B tokens", 124e6, 10e9, 8),
    ("Llama 3 8B, 15T tokens", 8e9, 15e12, 4096),
    ("Llama 3 405B, 15.6T tokens", 405e9, 15.6e12, 16384),
]:
    f, days, gh, usd = train_cost(n, d, g)
    print(f"{name:28s} C={f:.2e} FLOPs  {days:7.1f} days on {g} H100s  ~{gh/1e6:.2f}M GPU-h  ~${usd/1e6:.1f}M")

Why does one task teach so much? Predicting the next token of a Python function needs types, of a derivation needs algebra, of a dialogue needs the speakers. Loss keeps falling while any structure is left, so scale keeps paying off smoothly. That predictability lets a lab forecast a final loss from runs a thousand times smaller (section 03).

A pretraining project is mostly data and systems work around a small modeling core: collect, process, tokenize, choose a mixture, size the model, train, run late stages, release. Architecture is one step of eight.

Common confusions

  • Pretraining teaches the model to chat.

    A base model continues documents. Chat behavior is post-training.

  • More parameters is always better.

    Only for fixed data and compute. A too-big model on too few tokens loses to a smaller one trained longer (section 03).

  • 6ND is exact.

    It is accurate to roughly 10% for typical sizes and contexts, which is enough for planning.

  • Training tokens equal dataset size.

    Tokens seen can exceed unique tokens when good sources repeat for several epochs.

Check yourself

  1. A base model is prompted with "Q: Who wrote Hamlet?\nA:". Why does this format work better than the bare question?

    Show answer

    The Q/A scaffold makes "an answer follows" the most likely continuation. A bare question might be continued as part of a list of questions.

  2. Estimate the training FLOPs for a 7B model on 2T tokens.

    Show answer

    \(6 \times 7\times10^9 \times 2\times10^{12} = 8.4\times10^{22}\) FLOPs.

  3. Which pipeline steps take the most engineering time, and why?

    Show answer

    Data processing and distributed training. Data quality drives model quality per FLOP, and keeping thousands of GPUs busy through failures is a large systems problem. The model code is small.

  4. Why can't post-training fix a base model that has never seen any code?

    Show answer

    Post-training uses millions of tokens against trillions. It reshapes how existing knowledge is expressed; it cannot install a large body of new skill.

02Objectives

Next-token cross-entropy is the loss; a few tweaks keep it stable

A causal language model writes the probability of a text as a product of next-token probabilities. This is not an approximation: any distribution over sequences factorizes this way. Training minimizes the average negative log of those probabilities.

Teacher forcing. Training always conditions on the true previous tokens: the input is tokens[:-1], the target is tokens[1:], and the causal mask stops each position from peeking ahead. All T positions train in one parallel pass. The price is exposure bias: at inference the model reads its own outputs, which it never practiced on. At scale this matters less than early papers feared.

Packing. Documents are joined with an end-of-text token and cut into fixed sequences (for example 8,192 tokens). Most older models let attention cross document boundaries; Llama 3 masks it, which mattered for long-context training.

  • Weight decay (typically 0.1) applies to matrices but not to norm gains or biases: shrinking a gain toward 0 fights the normalization. OLMo 2 also dropped decay on embeddings for stability.
  • Tied vs untied embeddings. GPT-2 ties input and output embeddings. Large models usually untie them; small models tie them to save parameters (a 128K vocab at \(d=2048\) is 262M per matrix).
loss.py
# Cross-entropy, perplexity and z-loss on a toy vocabulary, stdlib only.
# Why log-sum-exp with max subtraction: raw exp() overflows for logits above ~700.
import math

def log_softmax(logits):
    m = max(logits)
    lse = m + math.log(sum(math.exp(z - m) for z in logits))
    return [z - lse for z in logits], lse

def lm_loss(logit_rows, targets, z_coef=1e-4):
    nll, zl = 0.0, 0.0
    for logits, y in zip(logit_rows, targets):
        logp, log_z = log_softmax(logits)
        nll += -logp[y]
        zl += z_coef * log_z ** 2
    T = len(targets)
    return nll / T, zl / T

V = 8
uniform = [[0.0] * V for _ in range(4)]
confident = [[5.0 if i == y else 0.0 for i in range(V)] for y in [1, 2, 3, 4]]
targets = [1, 2, 3, 4]

for name, rows in [("uniform", uniform), ("confident", confident)]:
    ce, z = lm_loss(rows, targets)
    print(f"{name:9s} loss={ce:.3f} nats  ppl={math.exp(ce):.2f}  z-loss={z:.5f}")
print(f"log(V) = {math.log(V):.3f}  (uniform loss should equal this, ppl should equal V)")
Common confusions

  • Loss 2.0 is better than loss 2.3, full stop.

    Only with the same tokenizer and eval set. Longer tokens raise per-token loss for the same text quality; use bits per byte across tokenizers.

  • Perplexity and accuracy move together.

    Mostly. A model can lower perplexity on easy tokens while the hard tokens benchmarks test stay put.

  • BERT is an older version of GPT.

    Different objective and architecture (bidirectional encoder vs causal decoder). Encoders remain the right tool for embeddings and classification.

  • z-loss is a regularizer for generalization.

    Its purpose is numerical stability, not better held-out loss.

  • Pre-norm and RMSNorm are the same idea.

    Pre-norm is where the norm sits; RMSNorm is which norm. Independent choices.

Check yourself

  1. Derive the gradient of \(\ell_t = \log\sum_j e^{z_j} - z_{x_t}\) with respect to \(z_i\).

    Show answer

    \(\partial/\partial z_i \log\sum_j e^{z_j} = e^{z_i}/Z = p_i\), and \(\partial z_{x_t}/\partial z_i = \mathbb{1}[i = x_t]\). So the gradient is \(p_i - \mathbb{1}[i=x_t]\).

  2. A model has validation loss 2.3 nats. What is its perplexity, and what does that mean?

    Show answer

    \(e^{2.3} \approx 10\). On average the model is as uncertain as a uniform choice among about 10 tokens.

  3. Why does BERT get less learning signal per forward pass than a causal LM?

    Show answer

    Only the masked 15% of positions contribute a loss, against 100% of positions in a causal LM.

  4. What failure does QK-norm prevent, and why does it show up only at scale or late in training?

    Show answer

    Unbounded growth of query and key norms makes attention logits huge, softmax saturates, and loss diverges. Weight norms grow slowly, so it appears after many steps, and worse at larger learning rates and widths.

  5. Why do we not apply weight decay to RMSNorm gains?

    Show answer

    Decay pulls the gain toward 0, which shrinks the normalized activations the norm exists to keep at unit scale. The optimizer then fights the decay for no benefit.

03Scaling

Loss follows a power law, so size and tokens can be planned

Train many models of different sizes and plot final loss on log-log axes: you get straight lines over many orders of magnitude. Loss falls as a power law in parameters, data and compute until it nears an irreducible floor, the entropy of text itself. Fit the curve on runs that cost thousands of dollars, then predict a run that costs tens of millions.

Epoch AI re-fitted the parametric form from the paper's plotted data and found the published constants inconsistent with the other two methods. The corrected fit (E ≈ 1.82, A ≈ 482, B ≈ 2085, α ≈ 0.348, β ≈ 0.366) agrees with the 20 tokens per parameter rule, and the code below uses it. The \(6ND\) rule itself: each weight does a multiply-add forward (2 FLOPs), and backward needs two matmuls per matrix (4 FLOPs).

Sardana et al. ("Beyond Chinchilla-Optimal") add expected inference tokens to the objective. The takeaway: 20:1 is a starting point, not a target.

  • Critical batch size. Up to it, doubling the batch halves the steps at no extra compute. Beyond it you burn compute for little gain. It grows as loss falls, so runs ramp up: Llama 3 405B went 4M, 8M, then 16M tokens per batch (typical: 1M to 16M).
  • muP. With standard parameterization the best LR depends on width. Maximal Update Parameterization rescales init and per-layer LR with width, so hyperparameters tuned on a small proxy transfer to the large model. Others fit LR-versus-size laws instead.

Loss spikes come from huge attention or output logits, bad data batches, too-high LR, or stale Adam variance on rarely updated parameters. Responses, in the order teams reach for them:

  1. Rewind to an earlier checkpoint and skip the offending batches (PaLM did this).
  2. Lower the LR, or tighten gradient clipping.
  3. Add QK-norm or z-loss.
  4. Lower \(\beta_2\) or raise \(\epsilon\).
schedules.py
# LR schedules plus a compute-optimal split, stdlib only.
import math

def cosine_lr(step, total, warmup, peak, floor_ratio=0.1):
    if step < warmup:
        return peak * step / warmup
    progress = (step - warmup) / max(1, total - warmup)
    floor = peak * floor_ratio
    return floor + 0.5 * (peak - floor) * (1 + math.cos(math.pi * progress))

def wsd_lr(step, total, warmup, peak, decay_frac=0.2):
    decay_start = int(total * (1 - decay_frac))
    if step < warmup:
        return peak * step / warmup
    if step < decay_start:
        return peak
    # Linear decay to 0; why: WSD's gains come from this short final cooldown.
    return peak * (total - step) / (total - decay_start)

total, warmup, peak = 10_000, 500, 3e-4
for s in [0, 250, 500, 2_500, 5_000, 8_000, 9_000, 10_000]:
    print(f"step {s:6d}  cosine {cosine_lr(s, total, warmup, peak):.2e}  wsd {wsd_lr(s, total, warmup, peak):.2e}")

# Chinchilla parametric fit, Epoch AI's corrected constants (see text).
E, A, B, alpha, beta = 1.82, 482.01, 2085.43, 0.3478, 0.3658

def compute_optimal(C):
    G = (alpha * A / (beta * B)) ** (1 / (alpha + beta))
    N = G * (C / 6) ** (beta / (alpha + beta))
    return N, C / (6 * N)

for C in [1e21, 5.76e23, 3.8e25]:
    N, D = compute_optimal(C)
    L = E + A / N ** alpha + B / D ** beta
    print(f"C={C:.1e}: N={N:.2e} params, D={D:.2e} tokens, D/N={D/N:.0f}, predicted loss={L:.3f}")
Common confusions

  • Chinchilla says always train at 20 tokens per parameter.

    It says that is the cheapest way to reach a given loss if training compute is all you pay for. With inference counted, smaller and longer is better.

  • Scaling laws predict benchmark scores.

    They predict loss. Mapping loss to accuracy needs a second fit (Llama 3 did this, section 08) and is noisier.

  • Kaplan was wrong.

    Its power-law form held up; its compute allocation was skewed by the fixed-schedule method.

  • A bigger batch is always faster.

    Faster per step, but past the critical batch size you pay more total compute per unit of loss reduction.

  • WSD is a different optimizer.

    It is only a learning-rate schedule; the optimizer is still AdamW.

Check yourself

  1. You have \(10^{23}\) FLOPs. What model size and token count does the 20:1 rule suggest?

    Show answer

    \(C = 6ND\) with \(D = 20N\) gives \(C = 120N^2\), so \(N = \sqrt{10^{23}/120} \approx 2.9\times10^{10}\) (about 29B params) and \(D \approx 580\)B tokens.

  2. Why train an 8B model on 15T tokens when Chinchilla suggests about 160B?

    Show answer

    Inference cost scales with N and dominates over a model's lifetime. The 8B keeps improving with more tokens, so extra training compute buys a cheaper-to-serve model at a given quality.

  3. Why does LLM pretraining use \(\beta_2 = 0.95\) instead of Adam's default 0.999?

    Show answer

    A shorter memory makes the second-moment estimate react quickly when gradient scales change, so a stale, too-small \(v\) is less likely to produce a huge update.

  4. What practical advantage does WSD give over cosine for scaling-law studies?

    Show answer

    Decay can be branched off any stable-phase checkpoint, so one run yields fully annealed models at many token budgets instead of one run per budget.

  5. A loss spike appears at step 120k and does not recover. List three things you could try.

    Show answer

    Rewind to a checkpoint before the spike and skip the batches around it; lower the peak LR; add QK-norm or z-loss; tighten gradient clipping. Also inspect the batch contents.

04Data

Data quality moves the model more than any architecture change

At fixed architecture and compute, data is the biggest lever on quality. A filtered web subset (FineWeb-Edu) lets a 1.8B model match on knowledge benchmarks what unfiltered data needs about 10× more tokens to reach. DCLM showed that the choice of quality classifier alone moved MMLU by double-digit points at 7B.

  • Reference-based filters use positives that resemble a trusted source (Wikipedia, pages it links to). GPT-3 and Llama used variants.
  • LLM-annotated filters (FineWeb-Edu) train on a strong model's grades.
  • Instruction-like positives: DCLM's best filter was fastText with positives from OpenHermes 2.5 and r/ExplainLikeImFive answers, and it beat fancier ones.

Model filters encode the biases of their positives: a Wikipedia-like filter can delete dialects, informal writing or whole topics. Track what you remove.

  • Upsample small high-quality sources (Wikipedia, textbooks) for several epochs; subsample huge low-quality ones. Up to about 4 epochs costs little against fresh data (Muennighoff et al.); beyond that returns fall fast.
  • Pick weights empirically: proxy models on candidate mixtures, mixture scaling laws, DoReMi, RegMix, or grid ablations.
  • Code and math are disproportionately valuable: code lifts reasoning and structured output even on non-code tasks. Both need their own extraction (indentation, LaTeX) and filters.
  • Order barely matters in the main phase, except at the end: upweight the best data while LR decays (annealing, section 06). It is also a cheap test of a new dataset.

Contamination. If benchmark items (MMLU, GSM8K) appear in training data, scores measure memorization. Decontamination checks n-gram overlap between training documents and test sets (GPT-3: 13-grams; Llama 3: 8-grams) and removes matches. Paraphrases and translations still slip through. Section 07 revisits it from the evaluation side.

PII and toxicity. Regexes mask emails, phone numbers and IP addresses. Toxicity filters (classifiers, word lists) also remove useful text on health, identity and history, so modern pipelines filter conservatively and leave behavior to post-training.

minhash.py
# MinHash near-duplicate detection sketch, stdlib only.
# Why salted SHA1 instead of 128 independent hash families: same statistical behavior, no deps.
import hashlib, random, re

def shingles(text, n=5):
    words = re.findall(r"\w+", text.lower())
    return {" ".join(words[i:i + n]) for i in range(max(1, len(words) - n + 1))}

def minhash(sh, num_perm=128):
    sig = []
    for seed in range(num_perm):
        salt = seed.to_bytes(4, "little")
        sig.append(min(int.from_bytes(hashlib.sha1(salt + s.encode()).digest()[:8], "little") for s in sh))
    return sig

def lsh_buckets(sig, bands=16, rows=8):
    return {(b, tuple(sig[b * rows:(b + 1) * rows])) for b in range(bands)}

random.seed(0)
base = " ".join(random.choice(["data", "model", "token", "train", "scale", "loss", "web", "text"]) + str(i % 37) for i in range(400))
near_dup = base.replace("loss3 ", "gain3 ", 2) + " subscribe to our newsletter"
unrelated = " ".join(random.choice(["cat", "dog", "tree", "river"]) + str(i) for i in range(400))

docs = {"base": base, "near_dup": near_dup, "unrelated": unrelated}
sets = {k: shingles(v) for k, v in docs.items()}
sigs = {k: minhash(s) for k, s in sets.items()}

for a, b in [("base", "near_dup"), ("base", "unrelated")]:
    true_j = len(sets[a] & sets[b]) / len(sets[a] | sets[b])
    est_j = sum(x == y for x, y in zip(sigs[a], sigs[b])) / len(sigs[a])
    candidate = bool(lsh_buckets(sigs[a]) & lsh_buckets(sigs[b]))
    print(f"{a} vs {b}: true J={true_j:.3f}  MinHash est={est_j:.3f}  LSH candidate={candidate}")
Common confusions

  • More data is always better.

    More good data is. Low-quality tokens at a fixed budget displace better ones.

  • Dedup everything as hard as possible.

    FineWeb found global cross-snapshot dedup hurt. Some repetition of good data is fine.

  • MinHash computes Jaccard similarity.

    It estimates it; the error shrinks as \(1/\sqrt{k}\) in the number of hash functions.

  • A quality classifier measures quality.

    It measures similarity to its positive examples. Choose positives carefully.

  • Decontamination guarantees clean evals.

    Paraphrases, translations and solutions in other formats slip past n-gram checks.

Check yourself

  1. Why re-extract text from WARC instead of using Common Crawl's WET files?

    Show answer

    WET keeps navigation, footers and boilerplate and mangles structure. Tools like trafilatura keep main content much more cleanly, and ablations show better downstream results.

  2. With 20 bands of 5 rows, roughly where is the LSH similarity threshold?

    Show answer

    \((1/20)^{1/5} \approx 0.55\) Jaccard (the left dashed line in the S-curve figure).

  3. Give one argument for and one against aggressive toxicity filtering in pretraining.

    Show answer

    For: fewer harmful generations and less offensive text memorized. Against: it removes legitimate content about health, identity and history, can hurt the model's ability to recognize toxicity, and is often biased against dialects.

  4. Why might deduplicating across all crawl snapshots hurt quality?

    Show answer

    Recrawled content tends to be popular and good. Global dedup keeps one copy of it but keeps every unique low-quality page, so the remaining distribution skews toward junk.

  5. How can annealing evaluate a new dataset cheaply?

    Show answer

    Take a partially trained checkpoint, run a short LR decay on a mix that includes the new data against a control mix, and compare benchmark scores. Much cheaper than a full pretraining ablation.

05Systems

Memory, not FLOPs, forces a model across thousands of GPUs

Why not train a 70B model on one 80 GB GPU? Count bytes. Mixed-precision Adam stores 16 bytes per parameter before any activation.

FSDP is PyTorch's ZeRO-3. Each layer's parameters are all-gathered just before use and freed after; gradients are reduce-scattered. Communication is about 1.5× plain data parallelism, often overlapped with compute.

  • Sequence parallelism pairs with TP: norms and dropout, which TP does not split, split along the sequence so their activations are not replicated.
  • Expert parallelism places mixture-of-experts experts on different GPUs (later in the course).
  • Global batch = micro-batch × gradient-accumulation steps × DP degree.

Recipe. Matmuls in bf16 with fp32 accumulation inside the tensor core. Master weights and optimizer states in fp32, because an update of about \(10^{-7}\) relative would round to zero in bf16. Softmax, norms and the loss in fp32. FP8 (E4M3 forward, E5M2 for gradients) doubles matmul throughput again on H100 but needs per-tensor or per-block scaling; DeepSeek-V3 trained mostly in FP8, Llama 3 in bf16.

Activation checkpointing trades compute for memory: keep each layer's input, recompute its forward during backward. Full recompute costs one extra forward (about 33% more compute). Selective recompute (Korthikanti et al.) redoes only cheap, memory-hungry parts such as the attention softmax, for a few percent.

Fault tolerance. At 16,000 GPUs something breaks every few hours. Save checkpoints often (weights, optimizer state, data loader position, RNG state); a 405B checkpoint with optimizer state is about 6 TB, so saving is sharded and asynchronous. Detect failures fast (collective watchdogs, NCCL tracing, health checks), keep hot spares, and load data deterministically so a restart resumes exactly. The metric is effective training time; Llama 3 reported over 90%.

Collective algorithms (ring, tree), topology (rail-optimized fat trees) and congestion control matter at scale. Even power is a systems issue: thousands of GPUs pausing together swing draw by megawatts.

memory.py
# Per-GPU memory and MFU calculator, stdlib only.
# Why ignore temporary buffers and fragmentation: this is a planning estimate, real usage runs ~10-20% higher.

def model_state_gb(params, zero_stage=0, dp=1):
    weights, grads, optim = 2 * params, 2 * params, 12 * params  # bf16 w, bf16 g, fp32 master + m + v
    if zero_stage >= 1: optim /= dp
    if zero_stage >= 2: grads /= dp
    if zero_stage >= 3: weights /= dp
    return (weights + grads + optim) / 1e9

def activation_gb(layers, seq, micro_batch, hidden, tp=1, checkpointing=False):
    per_layer = 34 * seq * micro_batch * hidden / tp  # FlashAttention: no s^2 term
    if checkpointing:
        per_layer = 2 * seq * micro_batch * hidden / tp  # only bf16 layer input kept, sharded by sequence parallelism
    return layers * per_layer / 1e9

def mfu(tokens_per_sec, params, gpus, peak=989e12):
    return tokens_per_sec * 6 * params / (gpus * peak)

P = 70e9
for stage in [0, 1, 2, 3]:
    print(f"70B ZeRO-{stage}, DP=64: model state {model_state_gb(P, stage, 64):7.1f} GB/GPU")
print(f"70B activations, 80 layers, s=8192, b=1, h=8192, TP=8: {activation_gb(80, 8192, 1, 8192, tp=8):.1f} GB/GPU")
print(f"  ...with full activation checkpointing: {activation_gb(80, 8192, 1, 8192, tp=8, checkpointing=True):.1f} GB/GPU")
print(f"MFU if 2048 H100s process 1.6M tokens/s on 70B: {mfu(1.6e6, P, 2048):.1%}")
Common confusions

  • Mixed precision halves memory.

    bf16 weights are half, but master weights and Adam states stay fp32, so model state is 16 bytes per parameter, the same as pure fp32 Adam (4+4+4+4). The win is speed and smaller activations.

  • FSDP is model parallelism.

    It shards storage, but each GPU still computes full layers on its own data. It is data parallelism with sharded state.

  • Tensor and pipeline parallelism are interchangeable.

    TP splits within a layer and needs NVLink-class bandwidth. PP splits across layers and tolerates slower links but adds bubbles.

  • Activation checkpointing makes training 2× slower.

    Full recompute adds about one forward pass, roughly a third of compute. Selective recompute adds a few percent.

  • MFU 100% is the goal.

    Unreachable; 40 to 50% at scale is excellent.

Check yourself

  1. How many bytes per parameter does mixed-precision Adam need for model state, and what are they?

    Show answer

    16: bf16 weights (2), bf16 grads (2), fp32 master weights (4), fp32 Adam \(m\) (4) and \(v\) (4).

  2. You have 64 GPUs with 80 GB each and a 30B model. Which ZeRO stage makes model state fit, ignoring activations?

    Show answer

    Total model state is 480 GB. ZeRO-1: \(2+2\) bytes × 30B = 120 GB plus \(12 \times 30\text{B}/64 \approx 5.6\) GB does not fit. ZeRO-2: 60 + 0.9 + 5.6 is about 67 GB, fits tightly. ZeRO-3: 7.5 GB, comfortable.

  3. Why is tensor parallelism kept inside a node?

    Show answer

    It does two all-reduces of activation-sized tensors per layer per pass, which only NVLink-class bandwidth sustains without stalling compute.

  4. A run reports 55% HFU with full activation checkpointing. Roughly what is its MFU?

    Show answer

    Recompute adds about one forward (\(2N\)) to the \(6N\), so hardware does \(8N\) per token: MFU ≈ 55% × 6/8 ≈ 41%.

  5. Why must a checkpoint include the data loader state?

    Show answer

    On restart you must resume at the same place in the data stream. Otherwise you repeat or skip data, which changes the effective mixture and breaks reproducibility.

06Late stages

Small objective and stage tweaks buy infilling, long context and a final boost

Plain next-token prediction on shuffled documents gets you most of the way. Modern runs add data transforms and training stages to buy specific capabilities.

Random character-level split points beat line-level ones. A left-to-right model cannot fill a gap given both sides, which is exactly what an editor cursor needs.

  • The trunk must support several future tokens, which encourages planning-like representations.
  • Memory trick: compute each head's loss and backward in sequence so you never hold \(n\) vocab-sized logit tensors at once.
  • At inference you can still generate one token at a time. The extra heads optionally draft tokens that are then verified.
  • DeepSeek-V3 uses a sequential variant (one extra token, predicted by a small module that also sees the next token's embedding) as an auxiliary loss and for speculation.

A prefix LM alone is rarely used for pure-text frontier models: two masking regimes complicate training and give no clear gain at scale. It does appear in multimodal models such as PaliGemma.

Long-context extension. Pretraining at 128K from the start would be wasteful: attention grows with length and most documents are short. So:

  1. Raise RoPE's base frequency \(\theta\) (for example from 10,000 to 500,000 or more) so long-distance rotations do not alias, or use Position Interpolation, NTK-aware scaling or YaRN.
  2. Continue on a mix that upweights genuinely long documents (books, long repositories, concatenated related documents), raising length gradually.
  3. Keep short-context data so short tasks do not regress.

Evaluate with needle-in-a-haystack and harder tests like RULER, since perplexity on long text can look fine while the model ignores distant context.

Mid-training and annealing. While LR decays to near zero the model is most sensitive to what it sees. Switch to a mix heavy in the best data (curated math, code, textbook-like and instruction-like text, sometimes synthetic) for the last few percent of tokens. OLMo 2 has a dedicated stage ("Dolmino" mix); Llama 3 annealed on the final 40M tokens. Gains on GSM8K can be large for small models and shrink for very large ones. Two warnings: benchmark-like data blurs into contamination, and part of the gain is format familiarity rather than new knowledge.

fim.py
# Fill-in-the-middle transform at character level, stdlib only.
# Why character-level split points: the paper found random character splits beat line-level ones for infilling quality.
import random

PRE, SUF, MID, EOT = "<PRE>", "<SUF>", "<MID>", "<EOT>"

def fim_transform(doc, rng, fim_rate=0.5, spm_rate=0.5):
    if rng.random() >= fim_rate:
        return doc + EOT  # Why keep plain docs: preserves normal left-to-right ability ("FIM-for-free").
    a, b = sorted(rng.sample(range(len(doc) + 1), 2))
    prefix, middle, suffix = doc[:a], doc[a:b], doc[b:]
    if rng.random() < spm_rate:
        return f"{PRE}{SUF}{suffix}{MID}{prefix}{middle}{EOT}"
    return f"{PRE}{prefix}{SUF}{suffix}{MID}{middle}{EOT}"

rng = random.Random(3)
doc = "def area(r):\n    return 3.14159 * r * r\n"
for _ in range(4):
    print(repr(fim_transform(doc, rng)))
Common confusions

  • FIM needs a new architecture or loss.

    It is a data transform plus three special tokens; the loss is still next-token cross-entropy.

  • Multi-token prediction means generating several tokens at once at inference.

    Training uses multiple heads. Inference can still emit one token at a time, with the extra heads optionally drafting tokens that are verified.

  • Long context is just a bigger max_position.

    Without RoPE scaling and long-data training, quality degrades sharply past the trained length.

  • Annealing is fine-tuning.

    It is still pretraining-style next-token loss on documents with a shifted mix and decaying LR. Post-training uses chat formats and other objectives.

  • UL2 replaced causal LM.

    It influenced thinking and some models, but most frontier LLMs use causal LM with FIM.

Check yourself

  1. Write the PSM form of the document "abcdef" split into prefix "ab", middle "cd", suffix "ef".

    Show answer

    <PRE>ab<SUF>ef<MID>cd<EOT>.

  2. Why does FIM at rate 0.5 not hurt left-to-right performance much?

    Show answer

    Half the documents are untouched, and even in transformed ones the model still predicts left to right on every token. The paper measured no significant loss in perplexity or benchmarks.

  3. What extra memory problem does multi-token prediction create, and how is it avoided?

    Show answer

    \(n\) heads produce \(n\) vocab-sized logit tensors per position. Compute and backpropagate each head's loss in sequence, freeing logits before the next head.

  4. Why not just pretrain at 128K context from the start?

    Show answer

    Attention compute and activation memory grow with length, most documents are short, and the long-range skill can be learned cheaply at the end with a few hundred billion tokens.

  5. What is a risk of putting benchmark-style math data in the annealing mix?

    Show answer

    It can inflate scores through format familiarity or near-duplicates of test items, which looks like capability but is closer to contamination.

07Evaluation

Pick evals that are cheap and smooth, and know their noise

A run takes weeks. You need to know early whether it is healthy, whether a data change helped, and which checkpoint to keep. That needs cheap, low-noise signals that move smoothly, which differ from how you grade a finished chat model.

Validation loss on several held-out sets (web, code, math, Wikipedia, each language) is smooth, cheap and tied to the objective. It is tokenizer-dependent, says little about task format, and can improve on web text while reasoning stalls. Use bits per byte to compare across tokenizers.

Prompt format, number of shots, normalization and answer parsing each move scores by several points, so numbers from different harnesses are not comparable. lm-evaluation-harness (EleutherAI) is the open standard, with hundreds of YAML-defined tasks. Also: lighteval (used for FineWeb ablations) and OLMES from AI2.

shell
lm_eval --model hf --model_args pretrained=gpt2 --tasks hellaswag,arc_easy --num_fewshot 0 --batch_size 16
  • Choose small-scale benchmarks that rise above chance early and monotonically. FineWeb picked tasks (CommonsenseQA, HellaSwag, OpenBookQA, PIQA, SIQA, WinoGrande, ARC, MMLU in cloze form) for low variance across seeds.
  • Average across several benchmarks; run multiple seeds for important comparisons.
  • Prefer smooth metrics (log-likelihood of the correct answer) over hard accuracy for small models.

Contamination, from the eval side. Detect it by n-gram overlap between test items and the corpus; by comparing scores on flagged versus clean items (Llama 3 reports this per benchmark); by checking whether the model completes a test question verbatim from its first half; and by fresh variants (GSM1K mirrors GSM8K and exposed overfit models). Treat a suspiciously large gain on one benchmark as contamination first.

Wei et al. (2022) documented emergent abilities: chance-level scores that jump at some scale. Schaeffer et al. (2023) showed many jumps are metric artifacts: with continuous metrics (edit distance, log-likelihood of the right answer) the same abilities improve smoothly. The consensus sits between: per-token loss is smooth and predictable, task metrics can still jump, and predicting them means modeling the loss-to-accuracy map, the two-step fit Llama 3 used (section 08).

loglik.py
# Log-likelihood multiple-choice scoring, the core of lm-evaluation-harness, stdlib only.
# Why a toy character bigram model: it shows the scoring logic without downloading weights; swap in a real LM's logprob.
import math
from collections import Counter

corpus = "the cat sat on the mat. the dog sat on the log. paris is the capital of france. " * 50
pairs = Counter(zip(corpus, corpus[1:]))
firsts = Counter(corpus[:-1])
vocab = sorted(set(corpus))

def logprob(context, continuation):
    # Why add-one smoothing: unseen pairs must not give log(0).
    lp, prev = 0.0, context[-1]
    for ch in continuation:
        lp += math.log((pairs[(prev, ch)] + 1) / (firsts[prev] + len(vocab)))
        prev = ch
    return lp

# Why report both: normalization can flip the pick, which is why harnesses report acc and acc_norm separately.
def score(question, options):
    raw = [logprob(question, o) for o in options]
    per_char = [lp / len(o) for lp, o in zip(raw, options)]
    return raw, per_char

q = "the capital of france is"
opts = [" paris.", " the dog sat on the log.", " xqz."]
raw, norm = score(q, opts)
for o, r, n in zip(opts, raw, norm):
    print(f"{o!r:30s} sum logprob={r:8.2f}  per-char={n:6.2f}")
print("pick (raw):", opts[max(range(3), key=raw.__getitem__)], "| pick (normalized):", opts[max(range(3), key=norm.__getitem__)])

# Why standard error matters: differences below ~2 SE are not evidence of improvement.
for n, p in [(1172, 0.5), (14042, 0.6), (164, 0.3)]:
    print(f"n={n:5d} acc={p:.2f}  standard error = {100 * math.sqrt(p * (1 - p) / n):.1f} points")
Common confusions

  • Lower validation loss means better benchmark scores.

    Usually correlated, but loss can improve on web text while reasoning stalls, or a mix change can trade one domain for another.

  • A 1-point gain on a benchmark is a real improvement.

    Often within noise; check the standard error and seeds.

  • Few-shot scores reflect what the chat model will do.

    Base few-shot scores measure latent capability. Chat models are usually evaluated zero-shot with different prompts.

  • Emergence was debunked.

    The metric artifact explains many cases, but sharp task-level transitions still exist and matter for planning.

  • MMLU at 25% means the model knows nothing.

    For small models in MCF format it may mean the model does not understand the A/B/C/D format. Try cloze.

Check yourself

  1. Why do evaluation harnesses often normalize log-likelihood by answer length?

    Show answer

    Each extra token adds a negative log-probability, so raw sums favor short answers regardless of correctness.

  2. A 1B model scores 25.3% on MMLU in MCF format. What would you try before concluding it lacks knowledge?

    Show answer

    Evaluate in cloze format (score answer text, not letters), and look at the log-probability of the correct answer as a continuous metric.

  3. Two runs differ by 1.2 points on ARC-Challenge. Is that meaningful?

    Show answer

    Probably not: the standard error is about 1.5 points at 50% accuracy with ~1,170 questions. You would need multiple seeds or a larger benchmark set.

  4. Explain the Schaeffer et al. argument in one or two sentences.

    Show answer

    Discontinuous metrics like exact match turn smooth gains in per-token probability into apparent sudden jumps. With continuous metrics the improvement looks smooth and predictable.

  5. Name two ways to detect benchmark contamination.

    Show answer

    N-gram overlap between test items and training data; comparing scores on flagged versus clean subsets; verbatim completion tests; fresh mirrored benchmarks.

08Llama 3

Llama 3 is a boring architecture run at huge scale with careful engineering

"The Llama 3 Herd of Models" (Meta, July 2024) is the most detailed public account of a frontier pretraining run. It ties together every section of this chapter. Section numbers below match the paper where noted.

  • Deliberately boring. A dense decoder-only transformer close to Llama 2. They avoided mixture-of-experts to maximize stability and spent effort on data, scale and infrastructure.
  • Pre-norm with RMSNorm, SwiGLU, RoPE with base 500,000 (eases 128K extension), no biases, GQA with 8 KV heads at every size.
  • 128K vocabulary (128,256 tokens: 100K from tiktoken plus 28K for non-English). English compression improved from 3.17 to 3.94 characters per token versus Llama 2.
  • An attention mask that blocks attention across document boundaries in a packed sequence. Little effect at 8K, important for long context.

Data: about 15T multilingual tokens (Llama 2: 1.8T; knowledge cutoff end of 2023). The pipeline matches section 04: a custom HTML parser that keeps math and code structure, PII and adult-content filters, three levels of dedup (URL, document MinHash, and line-level: lines appearing more than 6 times per bucket of 30M documents are removed, trading some good repeated text for less boilerplate), heuristics, fastText and RoBERTa quality classifiers, and separate code and math pipelines. Mix: 50% general, 25% math and reasoning, 17% code, 8% multilingual, chosen by scaling-law runs on small models. To judge a small special dataset they annealed a 50%-trained 8B to zero over 40B tokens with 30% weight on it.

Training recipe: AdamW, peak LR \(8\times10^{-5}\), linear warmup over 8,000 steps, cosine decay to \(8\times10^{-7}\) over 1.2M steps. Batch ramp: 4M tokens (4,096-token sequences), then 8M tokens (8,192) after 252M tokens, then 16M after 2.87T tokens. Few loss spikes, and no interventions for divergence. The mix shifted during training toward more non-English, math and recent web data.

  • Hardware: up to 16,384 H100 (80 GB HBM3, 700 W), 8 per server on NVLink, RoCE at 400 Gb/s per GPU (an InfiniBand cluster too). Storage: 240 PB at 2 to 7 TB/s, because checkpoints are huge.
  • DP is FSDP sharding optimizer state and gradients, keeping parameters unsharded after forward to avoid an extra all-gather.
  • A modified pipeline schedule allows a flexible number of micro-batches; first and last stages get one fewer layer because they hold the embedding and output.
  • Context parallelism is all-gather based, not ring attention: it works with the document mask, and KV is small thanks to GQA. A custom collective library (NCCLX) is tuned for their network.

Tools: PyTorch NCCL flight recorder for diagnosing hangs, automatic straggler detection, shorter job startup and checkpoint times. Two surprises: throughput varied 1 to 2% with time of day (datacenter temperature changed GPU clocks), and synchronized pauses across tens of thousands of GPUs caused power swings of tens of megawatts.

Training sets of common benchmarks were excluded from the annealing data to stay honest. The big model likely already had strong in-context abilities, so the data nudge did little.

  • The best-documented frontier run uses no exotic architecture. Gains came from 8× more and better data, compute-optimal sizing, and engineering for reliability.
  • Scaling laws made three distinct decisions: model size, data mix, benchmark predictions.
  • Every stage of this chapter shows up: objective and stability (02), scaling and schedules (03), data (04), systems (05), long context and annealing (06), evaluation and contamination (07).

Common confusions

  • Llama 3 405B is over-trained like the 8B.

    The 405B at about 39 tokens per parameter is close to compute-optimal per their own scaling law. The 8B (about 1,900) is the over-trained one.

  • Hardware failures mean bad engineering.

    At 16K GPUs, failures every few hours are a statistical certainty. The engineering is in recovery speed.

  • The 128K context came from training at 128K all along.

    Pretraining was at 8K. 128K came from a staged extension using about 5% of total tokens.

  • Annealing always helps big models.

    Their data shows big gains at 8B and negligible ones at 405B.

  • 4D parallelism means four times as many GPUs.

    It means four independent axes along which work is split; their product equals the GPU count.

Check yourself

  1. Why did Meta choose a dense model over mixture-of-experts for Llama 3?

    Show answer

    Training stability and simplicity; they preferred to put risk budget into scale and data rather than architecture.

  2. Verify that TP=8, CP=1, PP=16, DP=128 uses 16,384 GPUs. Why is TP the innermost dimension?

    Show answer

    \(8 \times 1 \times 16 \times 128 = 16{,}384\). TP needs the highest bandwidth (all-reduces every layer), which only NVLink inside a server provides, so it sits on the 8 GPUs of one server.

  3. How did Meta predict benchmark accuracy before training the 405B model?

    Show answer

    Two steps: fit compute to the normalized NLL of the correct answer on the benchmark, then fit NLL to accuracy with a sigmoid, using small models and older models.

  4. Compute the average time between unexpected interruptions in the 54-day snapshot.

    Show answer

    \(54 \times 24 / 419 \approx 3.1\) hours.

  5. What two conditions were checked before each context-length increase?

    Show answer

    Short-context benchmark performance had fully recovered, and needle-in-a-haystack retrieval worked at the new length.
