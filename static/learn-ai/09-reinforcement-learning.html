Chapter 6 · LLM Advanced

RL turns a score into a gradient

A language model is a policy, a response is an episode, and a reward arrives at the end. Every method here is log-probability times advantage, with a different way to estimate the advantage.

2 sections · needs: pretraining loss, SFT, reward models, DPO, KV cache, basic probability

01RL fundamentals

The policy gradient is log-probability times advantage

1.1 RL only tells the model how good its choices were

Supervised learning gives the right answer. RL gives a score, often much later. That fits things we can judge but not demonstrate: "was it helpful?", "is the proof correct?", "did the tests pass?". RL turns scores into gradients.

1.2 A response is an episode, a token is an action

An MDP is the tuple \((\mathcal{S}, \mathcal{A}, P, R, \gamma)\): states, actions, transitions, reward, discount. "Markov" means the next state depends only on the current state and action. For an LLM the state is the whole history, so this holds trivially. Fig. 1 is the mapping.

Many LLM algorithms treat the whole response as one action (a contextual bandit). That is a reasonable simplification, and with a terminal reward and \(\gamma = 1\), standard for LLMs.

1.3 Value, Q and advantage are one tree

The value \(V\) averages over what the policy might do. The Q function fixes the first action. The advantage is their gap, so it is positive for better-than-average actions and averages to zero.

In LLM terms: \(V(s)\) of a partial response is "how likely is this to end up correct?". \(A(s,a)\) of a token is "did it make success likelier than what the model usually writes here?".

1.4 Bellman equations: one reward plus the rest

Split the return into the first reward and the rest, and the value functions become recursive. Replace the policy average by a max and you get the optimal \(Q^*\), which underlies Q-learning and DQN. LLMs rarely use value-based methods: a max over 100k+ actions at every step, on a model that is already a good policy, makes policy-based methods the natural choice.

1.5 Exploration is sampling, and it has a ceiling

An agent that always takes its best guess never finds better. For LLMs, exploration comes from sampling temperature and from many responses per prompt. A pretrained model already proposes plausible actions, so the goal is diverse reasoning paths, not random tokens.

The flip side: RL can only reinforce what the model sometimes produces. If every sample for a prompt fails, the reward is constant and there is no signal. This exploration bottleneck is why curriculum and difficulty filtering matter in reasoning RL.

1.6 The policy gradient theorem in three moves

We want to maximize \(J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}[R(\tau)]\). The trajectory probability factorizes into the initial state, the policy terms and the dynamics. Step through what that buys.

1.7 A baseline removes the noise, not the signal

REINFORCE is unbiased but noisy. If every reward is positive, every sampled action is pushed up and only the relative sizes carry signal. Subtract a baseline \(b(s_t)\) that does not depend on the action. The natural choice is \(b = V^\pi\), which makes the weight an estimate of the advantage.

1.8 GAE dials between low variance and low bias

Actor-critic methods learn the baseline: an actor (the policy) and a critic \(V_\phi\) trained by regression toward observed returns. The critic gives advantages from TD errors without waiting for the full return. How far ahead to look is a bias-variance trade-off, and GAE exposes it as one knob \(\lambda\).

For LLMs the critic is usually another transformer of policy size with a scalar head at every token. With a sparse terminal reward, per-token advantages come entirely from the critic's changing predictions: if \(V\) jumps after a token, that token gets credit. That is the critic's promise (token-level credit) and its cost (another large model, hard to train on sparse rewards).

1.9 Trust regions: take a step the data can vouch for

The gradient gives a direction, not a step size. A big step can collapse the policy, and since the policy generates its own data, a collapsed policy poisons every later batch. We also want several gradient steps per batch of expensive rollouts. After the first step the data comes from the old policy, and importance sampling corrects for that.

1.10 PPO clips the ratio instead of constraining the KL

Write the ratio \(\rho_t = \pi_\theta(a_t\mid s_t)/\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)\). PPO takes the minimum of the plain and the clipped term. The result is a lower bound on the surrogate with no incentive to push \(\rho\) outside \([1-\varepsilon, 1+\varepsilon]\), so it runs several epochs of minibatch SGD per batch.

1.11 Code: REINFORCE on a toy sequence task

A toy with the shape of LLM RL: the policy emits \(L\) tokens one at a time, conditioned on the previous token. The episode ends after \(L\) tokens with one terminal reward, the fraction of positions that match a hidden target. Sequence is the episode, token is the action. Pure PyTorch, seconds on a CPU.

reinforce_toy.py
import torch
import torch.nn as nn

torch.manual_seed(0)
V, L, BATCH = 8, 6, 64
TARGET = torch.tensor([3, 1, 4, 1, 5, 2])
# All-positive rewards (like a reward model whose scores never go below zero) are where a missing baseline hurts most.
REWARD_SHIFT = 5.0
BOS = V  # an extra input id that marks the start, like a BOS token


class TinyPolicy(nn.Module):
    """Next-token distribution given (position, previous token): a minimal autoregressive LM."""

    def __init__(self):
        super().__init__()
        self.emb = nn.Embedding(V + 1, 32)
        self.pos = nn.Embedding(L, 32)
        self.head = nn.Linear(32, V)

    def forward(self, prev_tok, t):
        return self.head(torch.tanh(self.emb(prev_tok) + self.pos.weight[t]))


def rollout(policy):
    prev = torch.full((BATCH,), BOS)
    tokens, logps = [], []
    for t in range(L):
        dist = torch.distributions.Categorical(logits=policy(prev, t))
        tok = dist.sample()
        tokens.append(tok)
        logps.append(dist.log_prob(tok))
        prev = tok
    tokens = torch.stack(tokens, 1)
    # Reward only at the end, like a verifier scoring a finished answer.
    reward = (tokens == TARGET).float().mean(1) + REWARD_SHIFT
    return tokens, torch.stack(logps, 1), reward


def train(use_baseline: bool, steps=150):
    policy = TinyPolicy()
    opt = torch.optim.Adam(policy.parameters(), lr=1e-2)
    baseline = 0.0
    for step in range(steps):
        _, logps, reward = rollout(policy)
        # With gamma=1 and a terminal reward, every token's return-to-go equals the final reward.
        adv = reward - baseline if use_baseline else reward
        loss = -(logps.sum(1) * adv).mean()
        opt.zero_grad(); loss.backward(); opt.step()
        # A running mean is the simplest state-independent baseline; it is unbiased because it ignores the sampled actions.
        baseline = 0.9 * baseline + 0.1 * reward.mean().item()
    with torch.no_grad():
        return rollout(policy)[2].mean().item() - REWARD_SHIFT


if __name__ == "__main__":
    no_b = train(use_baseline=False)
    with_b = train(use_baseline=True)
    print(f"fraction of target matched, no baseline:   {no_b:.2f}")
    print(f"fraction of target matched, with baseline: {with_b:.2f}")
    assert with_b > 0.9 and with_b > no_b, "the baseline should solve the toy faster"

Without a baseline every sequence scores near 5 and is pushed up, so only small differences carry signal. With the baseline, below-average sequences get a negative weight and the toy is solved in the same budget. Try these:

  • Set REWARD_SHIFT = 0: the gap shrinks.
  • Shrink BATCH and compare curves over several seeds.
  • Use the mean reward of the other samples as the baseline: you have just invented RLOO (2.8).
  • Reward 1 only if the whole sequence matches (sparse, like math correctness) and watch exploration fail.
Common confusions

  • The reward is differentiated.

    Never. Policy gradient differentiates log-probabilities of sampled actions. The reward is only a weight.

  • A baseline biases the gradient.

    Not if it ignores the action being scored. It changes variance only.

  • V and Q are the same for LLMs because transitions are deterministic.

    \(Q(s,a) = r + V(s')\), but \(V(s)\) still averages over the policy's future sampling. They stay different functions.

  • PPO's clip limits the KL.

    It removes the incentive to move ratios far from 1 on sampled actions. The KL can still drift over many epochs, so many implementations monitor it and stop early.

  • Discounting is needed.

    With finite episodes and a terminal reward, \(\gamma = 1\) is standard. Discounting would penalize long correct answers.

  • An episode is a token.

    An episode is the full response. A token is one action inside it.

Check yourself

  1. In the LLM MDP, what are the state, action, transition and episode? Why is the transition trivial?

    Show answer

    State: prompt plus tokens so far. Action: the next token. Transition: append the token. Episode: one response up to EOS or the length limit. It is trivial because the environment is string concatenation; all randomness comes from the policy, the prompt distribution and the reward.

  2. Show that the dynamics \(P(s'\mid s,a)\) do not appear in \(\nabla_\theta \log p_\theta(\tau)\). Why does it matter?

    Show answer

    \(\log p_\theta(\tau) = \log\rho(s_0) + \sum_t \log\pi_\theta(a_t\mid s_t) + \sum_t \log P(s_{t+1}\mid s_t,a_t)\). Only the policy terms depend on \(\theta\). So gradients come from samples without modeling the environment or the reward function.

  3. Prove a state-dependent baseline leaves the gradient unbiased. What breaks if it depends on the action?

    Show answer

    \(\mathbb{E}_{a\sim\pi}[\nabla\log\pi(a\mid s)\,b(s)] = b(s)\nabla\sum_a\pi(a\mid s) = b(s)\nabla 1 = 0\). If \(b\) depends on \(a\), it cannot leave the sum, the term no longer vanishes, and the gradient is biased.

  4. With a terminal reward \(r\), \(\gamma=1\) and no critic, what is the REINFORCE weight on each token? What does that imply for credit assignment?

    Show answer

    Every token gets weight \(r\) (or \(r-b\)). All tokens of a good response are reinforced equally, including irrelevant or harmful ones. Credit assignment relies on averaging over many samples.

  5. What do \(\lambda=0\) and \(\lambda=1\) correspond to in GAE?

    Show answer

    \(\lambda=0\): one-step TD advantage \(\delta_t\), low variance, biased by critic errors. \(\lambda=1\): Monte Carlo advantage \(G_t - V(s_t)\), unbiased but high variance.

  6. An action has \(\hat A>0\) and ratio 1.35 with \(\varepsilon=0.2\). What is the PPO gradient for that sample?

    Show answer

    Zero. With \(\hat A>0\) and \(\rho>1.2\) the min picks the clipped term \(1.2\hat A\), which is constant in \(\theta\). The action has already moved far enough.

02RLHF and GRPO

Every RLHF method is one gradient with a different advantage

2.1 InstructGPT: SFT, reward model, then PPO

InstructGPT (Ouyang et al. 2022) is the template every later system modifies. It also mixed pretraining gradients into PPO ("PPO-ptx") to limit regressions on public benchmarks, the alignment tax.

2.2 The KL penalty rides on every token

The reward model is only accurate near the SFT outputs it was trained on. Without a penalty the policy drifts to places where the reward model is high for bad reasons. The KL keeps text fluent and diverse. DPO solves this same objective in closed form; PPO solves it by sampling.

2.3 PPO for LLMs keeps four models in memory

Details that matter: whiten advantages per batch, initialize the critic from the reward model, mask padding and prompt tokens out of every loss, monitor KL, length, reward and value loss together, and use a large prompt batch because the gradient is noisy. The memory burden is a big reason DPO took off, and why GRPO and RLOO drop the critic.

2.4 Online RL gets feedback on what the model does now

2.5 Push a proxy hard enough and the true score falls

The reward model is a learned proxy (Goodhart's law). Symptoms: ever longer answers (length bias), hedging and flattery, formatting for its own sake, and repeated phrases the model likes. With verifiable rewards, hacking looks like exploiting the checker: the right format without solving, special-casing tests.

2.6 RLAIF swaps human labels for model labels

  • Constitutional AI (Bai et al. 2022): the model critiques and revises its outputs against written principles, and an AI labeler produces harmlessness preferences for the reward model.
  • RLAIF vs RLHF (Lee et al. 2023): an off-the-shelf LLM labeler led to policies rated comparably to RLHF on summarization and dialogue. They also tried the LLM's score directly as the reward.

Most open preference data today (Tulu 3, UltraFeedback-style) is AI-labeled, often audited by humans. Reward hacking still applies, plus biases inherited from the judge.

2.7 RLVR drops the reward model, GRPO drops the critic

RLVR (RL with verifiable rewards, named in Tulu 3) skips the reward model when correctness can be checked: math answers against a reference, code against tests, constraints against a checker. The reward is usually binary, sometimes with a small format reward. A verifier cannot be flattered, which cuts hacking a lot but not to zero.

With long chain-of-thought, RLVR produced the reasoning models. DeepSeek-R1-Zero applied RL straight to the V3 base with only accuracy and format rewards (reasoning in <think> tags). Response length grew from hundreds to thousands of tokens and the model learned to re-check and backtrack (the "aha moment"). DeepSeek-R1 made this usable with a four-stage pipeline.

GRPO: the group mean replaces the critic

GRPO (DeepSeekMath, Shao et al. 2024) starts from the baseline form (1.7). The ideal baseline for prompt \(q\) is \(V(q)\), the policy's expected reward on \(q\). Estimate it by Monte Carlo: sample a group of \(G\) responses, score them, and use their mean. Then divide by the standard deviation.

2.8 RLOO, Dr. GRPO and DAPO fix what GRPO leaves rough

RLOO (Ahmadian et al. 2024) treats the whole response as one action, samples \(k\) responses per prompt, and uses the leave-one-out mean as each sample's baseline. That baseline ignores sample \(i\), so the estimator is exactly unbiased. It is plain REINFORCE with a baseline, what you built in 1.11.

Dr. GRPO (Liu et al. 2025) finds two biases in GRPO's normalizations.

  1. Length bias. For positive advantages this favors short correct answers. For negative advantages it penalizes long wrong answers less per token, so wrong answers drift longer. Part of the "length grows during RL" effect is this artifact.
  2. Difficulty bias. Dividing by std scales up prompts where almost all samples agree (very easy or very hard), overweighting them against medium prompts.

The fix: drop the std division and replace \(1/|o_i|\) with a constant normalizer such as the maximum generation length. The objective is then an unbiased policy gradient, with shorter wrong answers at similar accuracy.

DAPO (Yu et al. 2025, ByteDance Seed) makes four practical changes and reached 50 on AIME 2024 with Qwen2.5-32B base. It also removes the KL term, since for long CoT the policy is supposed to move far from the initial model.

All of these share one template: \(\nabla\log\pi \times \hat A\), with choices for the baseline, the normalization and the trust region.

2.9 Code: GRPO advantages and loss

The three agg modes are GRPO (seq_mean), DAPO (token_mean) and Dr. GRPO (constant). Run it and read the printed gradients: under seq_mean the length-3 response gets a larger per-token gradient than the length-5 one despite equal advantage magnitudes. That is the length bias in two lines of output.

grpo.py
import torch


def grpo_advantages(rewards: torch.Tensor, scale_by_std: bool = True, eps: float = 1e-6):
    """rewards: [num_prompts, G] -> advantages of the same shape."""
    mean = rewards.mean(dim=1, keepdim=True)
    adv = rewards - mean
    if scale_by_std:  # Dr. GRPO sets this False to avoid over-weighting near-unanimous groups.
        adv = adv / (rewards.std(dim=1, keepdim=True) + eps)
    return adv


def grpo_loss(logp, old_logp, ref_logp, adv, mask,
              clip_low=0.2, clip_high=0.2, beta=0.04, agg="seq_mean", max_len=None):
    """
    logp, old_logp, ref_logp, mask: [B, T] per-token tensors for B = num_prompts * G responses.
    adv: [B] one advantage per response.
    agg: "seq_mean" (GRPO), "token_mean" (DAPO), "constant" (Dr. GRPO).
    """
    adv = adv.unsqueeze(1)  # every token of a response shares its outcome advantage
    ratio = torch.exp(logp - old_logp)
    unclipped = ratio * adv
    clipped = torch.clamp(ratio, 1 - clip_low, 1 + clip_high) * adv
    pg = torch.min(unclipped, clipped)

    # k3 estimator: non-negative per token and lower variance than the raw log-ratio.
    log_r = ref_logp - logp
    kl = torch.exp(log_r) - log_r - 1

    per_token = -(pg - beta * kl) * mask
    if agg == "seq_mean":
        return (per_token.sum(1) / mask.sum(1).clamp(min=1)).mean()
    if agg == "token_mean":
        return per_token.sum() / mask.sum().clamp(min=1)
    if agg == "constant":
        return per_token.sum() / (per_token.shape[0] * (max_len or per_token.shape[1]))
    raise ValueError(agg)


if __name__ == "__main__":
    torch.manual_seed(0)
    P, G, T = 2, 4, 5
    rewards = torch.tensor([[1., 0., 0., 1.], [0., 0., 0., 0.]])
    adv = grpo_advantages(rewards).flatten()
    print("advantages:", adv.view(P, G))
    assert torch.allclose(adv[4:], torch.zeros(4)), "all-equal group gives no signal"

    lengths = torch.tensor([5, 3, 4, 2, 5, 5, 1, 3])
    mask = (torch.arange(T)[None, :] < lengths[:, None]).float()
    logp = (torch.randn(P * G, T) * 0.1 - 1.0).requires_grad_(True)
    old_logp = logp.detach().clone()  # first PPO epoch: policy equals the sampler
    ref_logp = old_logp + 0.05 * torch.randn_like(old_logp)

    for agg in ("seq_mean", "token_mean", "constant"):
        loss = grpo_loss(logp, old_logp, ref_logp, adv, mask, agg=agg, beta=0.0)
        (g,) = torch.autograd.grad(loss, logp)
        # With ratio == 1, the gradient on each token's logp is -adv times its aggregation weight.
        print(agg, "grad on token 0 per response:", [round(v, 3) for v in g[:, 0].tolist()])
        assert (g[:4, 0].sign() == -adv[:4].sign()).all()

In a real trainer, logp comes from a forward pass of the policy on the sampled tokens, old_logp from the policy at rollout time (often recomputed by the training engine, since inference-engine log-probs differ slightly), and ref_logp from the frozen reference.

2.10 Process rewards help search, outcome rewards win in RL

  • "Let's Verify Step by Step" (Lightman et al. 2023) released PRM800K, 800k step labels on MATH, and found process supervision gave a better best-of-\(N\) verifier.
  • Math-Shepherd (Wang et al. 2023) labels steps automatically by rolling out from each step and counting how often it reaches the right answer, a Monte Carlo estimate of \(V(s_t)\).
  • In large-scale RL, PRMs have fared worse. R1 lists them among failed attempts: steps are hard to define, labels are noisy, and a learned PRM invites hacking and needs retraining as the policy moves. They stay useful for search and reranking.

2.11 Test-time compute is the other scaling axis

Snell et al. (2024) showed that spending test-time compute adaptively by prompt difficulty can beat a 14x larger model in FLOPs-matched comparisons, on problems where the base model already has some success. RL training compute and test-time compute are now scaling axes alongside pretraining.

Common confusions

  • GRPO has no KL.

    Original GRPO has a KL term in the loss. Some later recipes (DAPO) remove it.

  • GRPO does not need a reward model.

    It does not need a critic. It still needs a reward: a learned reward model or a verifier.

  • The reference model and the old policy are the same.

    \(\pi_{\mathrm{ref}}\) is frozen (the SFT model) and anchors the KL. \(\pi_{\theta_{\mathrm{old}}}\) is the snapshot that generated this batch and defines the PPO ratio. They coincide only at the very start.

  • A higher reward model score means a better model.

    Only up to the overoptimization peak. Past it, true quality falls while the proxy rises.

  • Longer responses mean better reasoning.

    Some length growth is an artifact of per-response normalization (Dr. GRPO).

  • RLVR cannot be hacked.

    Weak verifiers can (format tricks, test special-casing). Verifier quality is part of reward design.

  • DPO and PPO optimize different objectives.

    Same KL-regularized objective. DPO uses offline pairs and a closed-form reparameterization; PPO samples online.

Check yourself

  1. List the four models in PPO-based RLHF, which are trained, and which GRPO removes.

    Show answer

    Policy (trained), reference (frozen), reward model (frozen), critic (trained). GRPO removes the critic.

  2. Why does PPO-RLHF put a per-token KL penalty into the reward? What happens with \(\beta=0\) against a learned reward model?

    Show answer

    The reward model is only reliable near the reference distribution, and the per-token KL keeps the policy there and gives a dense signal. With \(\beta=0\) the policy drifts to regions that exploit reward model errors (length, flattery, odd patterns), and true quality eventually falls (Gao et al.).

  3. Derive GRPO's advantage as a Monte Carlo baseline. What happens to the gradient when all \(G\) responses are correct?

    Show answer

    The ideal baseline is \(V(q) = \mathbb{E}_{o\sim\pi}[r(q,o)]\). Averaging \(G\) sampled rewards estimates it, and subtracting gives the advantage, normalized by the group std. If all are correct, every \(r_i\) equals the mean, all advantages are zero, and only the KL term produces gradient.

  4. How does RLOO's baseline differ from GRPO's group mean, and why is RLOO unbiased?

    Show answer

    RLOO uses the mean of the other \(k-1\) rewards, which does not depend on sample \(i\)'s action, so the baseline argument from 1.7 applies exactly. GRPO's mean includes \(r_i\), but \(r_i - \mathrm{mean}(r)\) is \(\frac{G-1}{G}\) times the leave-one-out advantage, so by itself it only rescales the gradient. GRPO's bias comes from the std division and the \(1/|o_i|\) normalization.

  5. Explain Dr. GRPO's length bias for both positive and negative advantages.

    Show answer

    Each token's gradient weight is \(\hat A_i/|o_i|\). For correct responses, shorter ones get stronger per-token reinforcement. For wrong responses, longer ones get weaker per-token penalties, so being wrong at length costs less and incorrect answers grow.

  6. Name DAPO's four techniques and the problem each addresses.

    Show answer

    Clip-Higher (entropy collapse; lets low-probability tokens rise). Dynamic sampling (zero-advantage groups waste batch slots). Token-level loss (long responses underweighted, long bad patterns under-penalized). Overlong reward shaping (truncation adds reward noise).

Train a small reasoning model with GRPO, then break it on purpose

Run GRPO on a verifiable math task, ablate its normalizations, then swap in a weak verifier and watch the model exploit it.

  1. Setup. Take a 0.5B to 1.5B instruct model (for example Qwen2.5 Instruct) and GSM8K. Write a verifier: extract the final answer from <answer>...</answer> and compare it to the reference. Reward = 1 if correct, plus 0.1 for correct format.
  2. Baseline. Measure pass@1 and pass@8 on a held-out split before training.
  3. Train with TRL's GRPOTrainer (or your own loop using the grpo_loss above and vLLM rollouts) with \(G=8\). Log mean reward, response length, KL to reference, entropy, and the fraction of zero-advantage groups.
  4. Ablations, each a short run with everything else fixed: scale_by_std on vs off with agg = seq_mean vs token_mean vs constant (plot response length for correct and incorrect answers separately); \(\beta=0.04\) vs \(\beta=0\); symmetric clip vs Clip-Higher with \(\varepsilon_{\mathrm{high}}=0.28\) (plot entropy).
  5. Reward hacking. Replace the verifier with a weak one, for example one that rewards any response containing a number equal to the answer anywhere. Train, find what the model learns to exploit, then fix the verifier.
  6. Report. Final pass@1 and pass@8 for each setting, plots, and a paragraph on two questions: did RL improve pass@8 or mainly pass@1 (sharpening vs new capability)? Which normalization would you choose, and why?
  • Baseline and trained pass@1 and pass@8 for every setting.
  • Plots: response length by correctness, entropy, zero-advantage fraction.
  • A weak-verifier run that exposes an exploit, and the fixed verifier.
  • The written answer on sharpening vs new capability, and your choice of normalization.
