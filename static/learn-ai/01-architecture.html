Chapter 1 · LLM Fundamentals

Architecture: text in, next-token scores out

Text becomes tokens, tokens become vectors, and a stack of blocks turns them into one score per possible next token. By the end you have written GPT-2 and loaded OpenAI's weights.

7 sections · needs: Python and PyTorch (tensors, nn.Module, autograd), matmul and shapes like (B, T, C), softmax, cross-entropy, gradient descent · Python 3.10+ with torch, tiktoken, transformers

01Introduction

A language model is a next-token scorer, run in a loop

A language model is a function from a token sequence to a probability distribution over the next token. Given "The capital of France is", a trained model puts most of its mass on " Paris". Everything else an LLM does is that one function run in a loop.

The design rests on two parts. Attention is the only place where information moves between positions. The MLP (a small two-layer network) processes each position alone, and holds much of the stored knowledge. "Decoder-only" means each position may look only at earlier positions, which is exactly what next-token prediction needs.

Before any neural network, the whole idea fits in a lookup table: count which character follows which, then sample autoregressively. A transformer replaces the count table with a learned function that sees the entire history.

counting_lm.py
import random
from collections import Counter, defaultdict

text = "the cat sat on the mat. the cat ate the rat. the rat sat on the cat."

# The "model": for each character, how often each next character follows it.
counts = defaultdict(Counter)
for a, b in zip(text, text[1:]):
    counts[a][b] += 1

def next_char_distribution(prev):
    c = counts[prev]
    total = sum(c.values())
    return {ch: n / total for ch, n in c.items()}

print(next_char_distribution("t"))  # p(next | 't')

random.seed(0)
out = "t"
for _ in range(40):
    dist = next_char_distribution(out[-1])
    # Sampling, not argmax: argmax would loop on the single most common pair.
    out += random.choices(list(dist), weights=list(dist.values()))[0]
print(out)
Common confusions

  • The model outputs a word.

    It outputs a distribution over the whole vocabulary. Choosing a token is a separate step (sampling) with its own knobs.

  • The model remembers the conversation.

    It is stateless between calls. "Memory" is the transcript fed back in as input. Anything outside the context window does not exist for it.

  • Decoder-only means it cannot understand input.

    The prompt goes through the same stack. Decoder-only only means each position sees earlier positions and not later ones.

  • Transformers replaced RNNs because they are smarter.

    Mostly because they parallelize during training, so people could train far larger models on far more data.

  • Generation is parallel too.

    Training is parallel across positions. Generation is sequential, one token per forward pass. Section 05 covers the KV cache that makes this bearable.

Check yourself

  1. Write the chain-rule factorization of \(p(\text{"a b c"})\) into three conditional terms.

    Show answer

    \(p(a)\,p(b \mid a)\,p(c \mid a, b)\).

  2. Why can a transformer get \(T\) training signals from one sequence of length \(T\) in a single forward pass?

    Show answer

    The causal mask lets every position compute its own prediction from earlier positions only, so all \(T\) predictions are computed at once and each is compared to the true next token.

  3. Name the two sub-layers of a transformer block and say which one moves information between positions.

    Show answer

    Attention and the MLP. Attention moves information between positions; the MLP works on each position independently.

  4. What was the main practical advantage of the 2017 Transformer over LSTMs?

    Show answer

    Parallelism during training (no step-by-step recurrence) plus direct connections between any two positions. That made it cheaper to train at scale and better at long-range dependencies.

  5. What did GPT-3 demonstrate that GPT-1 did not?

    Show answer

    In-context learning (new tasks from a few prompt examples, no fine-tuning) and that capabilities improve smoothly with scale.

02Tokenization

Subword tokens trade sequence length against vocabulary size

A network needs numbers, so text is chopped into units and each unit gets an integer ID. The choice of unit is a trade-off between sequence length and vocabulary size.

Encoding new text replays the merge rules in the order they were learned: split into base symbols, then keep applying the earliest-learned merge that is present. Decoding looks up each token's string and concatenates. The product of training is the ordered list of merges.

  • SentencePiece is a library, not an algorithm. It runs BPE or Unigram on a raw stream (spaces become the visible symbol ▁), with no language-specific pre-tokenizer. Llama 1 and 2 used SentencePiece BPE with a 32k vocabulary and byte fallback.
  • tiktoken is OpenAI's fast Rust byte-level BPE. It only encodes and decodes. It ships gpt2 (50k), cl100k_base (about 100k, GPT-3.5 and GPT-4) and o200k_base (about 200k, GPT-4o). Llama 3 uses a tiktoken-based 128k tokenizer.

Two more pitfalls. Glitch tokens are frequent in the tokenizer's data but almost absent from the model's, like " SolidGoldMagikarp" in GPT-2, so their embeddings are nearly untrained. Code whitespace: GPT-2 spent a token per indentation space; later tokenizers added tokens for runs of spaces.

tiny_bpe.py
from collections import Counter

def get_pair_counts(ids):
    return Counter(zip(ids, ids[1:]))

def merge(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i < len(ids) - 1 and (ids[i], ids[i + 1]) == pair:
            out.append(new_id)
            i += 2
        else:
            out.append(ids[i])
            i += 1
    return out

text = "low lower lowest newer newest wider widest " * 20
ids = list(text.encode("utf-8"))  # byte-level: base vocab is 0..255
merges = {}
for step in range(10):
    pair = get_pair_counts(ids).most_common(1)[0][0]
    new_id = 256 + step
    ids = merge(ids, pair, new_id)
    merges[pair] = new_id

vocab = {i: bytes([i]) for i in range(256)}
for (a, b), i in merges.items():  # dicts keep insertion order, so parents exist first
    vocab[i] = vocab[a] + vocab[b]
print([vocab[i].decode() for i in merges.values()])
print(f"compression: {len(text.encode())} bytes -> {len(ids)} tokens")

import tiktoken
enc = tiktoken.get_encoding("gpt2")
for s in ["hello world", " hello world", "strawberry", "1234567", "Привет мир"]:
    toks = enc.encode(s)
    print(repr(s), toks, [enc.decode([t]) for t in toks])

Run it and notice the learned merges (we, st, lowe, newe), the changed tokens from a leading space, and the extra tokens Russian needs. Decoding one token alone can show a broken character when it holds only part of a multi-byte UTF-8 character; that is expected.

Common confusions

  • Tokens are words.

    They are subword pieces: about 0.75 English words per token, fewer for other languages and code.

  • The tokenizer is learned with the model.

    It is trained separately beforehand, usually on a different data sample, then frozen. The model only sees integer IDs.

  • BPE encoding picks the longest matching token.

    It replays learned merges in priority order. The result is usually, not always, the same as greedy longest-match.

  • SentencePiece is an alternative to BPE.

    SentencePiece is a library that can run BPE or Unigram.

  • Token ID numbers mean something.

    IDs are arbitrary labels (in BPE, roughly merge order). Meaning lives in the embedding vectors.

Check yourself

  1. Why does byte-level BPE never produce an unknown token?

    Show answer

    Every string is UTF-8 bytes and all 256 byte values are in the base vocabulary, so any input is representable, in the worst case as one token per byte.

  2. In BPE, what exactly is saved after training, and how is it used to encode new text?

    Show answer

    The ordered list of merge rules (plus the resulting vocabulary). Encoding splits text into bytes and repeatedly applies the earliest-learned merge present until none apply.

  3. Give two reasons a model might be bad at reversing the letters of a word.

    Show answer

    It sees token IDs, not letters, so it must remember each token's spelling; and the reversed string tokenizes into completely different, often rare, pieces.

  4. You double the vocabulary of a model with \(d_{\text{model}} = 4096\) from 32k to 64k. How many parameters does that add to the input embedding?

    Show answer

    \(32{,}000 \times 4096 \approx 131\) million (and the same again for the output layer if it is not tied).

  5. Why does GPT-2 pre-tokenize with a regex before running BPE?

    Show answer

    To stop merges crossing category boundaries (letters with punctuation, words with following spaces), which would waste vocabulary on near-duplicates like "dog.", "dog!", "dog?".

03The Embedding Layer

An embedding is a table lookup, and the output layer reads the same table

Token IDs are labels, not quantities: token 3797 is not "more" than 464. A network multiplies and adds its inputs, so raw IDs would impose a fake order. Each token instead gets a learned vector.

Tying is common in small and medium models (GPT-2, Gemma, Llama 3.2 1B and 3B). Larger models often untie: the input side must say "what is this token", the output side "what would come next", and those are not exactly the same job.

embedding.py
import torch
import torch.nn as nn
import torch.nn.functional as F

V, d = 10, 4
emb = nn.Embedding(V, d)
ids = torch.tensor([[3, 7, 3]])                  # (B=1, T=3)

x_lookup = emb(ids)                               # (1, 3, 4)
one_hot = F.one_hot(ids, num_classes=V).float()   # (1, 3, 10)
x_matmul = one_hot @ emb.weight                   # (1, 3, 10) @ (10, 4) -> (1, 3, 4)
print(torch.allclose(x_lookup, x_matmul))         # True: same operation

lm_head = nn.Linear(d, V, bias=False)             # weight shape (V, d), computes x @ W.T
lm_head.weight = emb.weight                       # tie: one tensor, two roles
logits = lm_head(x_lookup)                        # (1, 3, 10)
print(logits.shape, lm_head.weight is emb.weight)

# Same token in, same vector out: the embedding has no idea about context yet.
print(torch.equal(x_lookup[0, 0], x_lookup[0, 2]))

nn.Linear(d, V) stores its weight as (V, d) and computes x @ W.T, which is why the embedding matrix (V, d) can be assigned to it with no transpose.

Common confusions

  • The embedding layer is a separate pretrained model, like word2vec.

    In LLMs it is the first weight matrix of the network, trained from scratch together with everything else.

  • Embedding vectors are the model's understanding of a word.

    They are a context-free starting point. The same token has the same input embedding in every context.

  • An embedding lookup and a linear layer are different things.

    A lookup is a linear layer applied to a one-hot vector, implemented efficiently.

  • Weight tying means input and output vectors of a token are identical at every layer.

    It only means \(W_U = W_E^\top\). The final hidden state scored against \(W_U\) has gone through the whole network.

  • Bigger \(d_{\text{model}}\) is only about embeddings.

    \(d_{\text{model}}\) is the width of the whole residual stream, so it sets the size of nearly every weight matrix.

Check yourself

  1. What is the shape of GPT-2 small's embedding matrix, and how many parameters is that?

    Show answer

    (50257, 768): \(50{,}257 \times 768 = 38{,}597{,}376 \approx 38.6\)M.

  2. Why is multiplying a one-hot vector by \(W_E\) never done explicitly?

    Show answer

    It selects one row, so indexing W_E[id] gives the same result without wasted multiply-by-zero work or a V-sized vector in memory.

  3. With weight tying, how does the logit for token \(j\) relate to token \(j\)'s input embedding?

    Show answer

    It is the dot product of the final hidden vector with token j's embedding row: \(\text{logit}_j = x \cdot W_E[j]\).

  4. A token appears only once in the training data. Why might weight tying help its embedding?

    Show answer

    The row gets gradient from the output softmax at every position (pushed down when it is not the answer), not only on the one occasion it is an input.

  5. Why can't an input embedding distinguish two meanings of " bank"?

    Show answer

    The lookup depends only on the token ID, which is identical in both cases. Only attention to surrounding tokens can disambiguate.

04Positional Encoding

Attention is blind to order, so position must be injected

Attention builds each output as a weighted average of vectors, with weights from vector similarity. Nothing in that refers to where a token sits.

Low-index pairs rotate fast and encode local position. High-index pairs rotate slowly and act almost like position-free channels for content matching over long distances. Porting checkpoints: the paper pairs adjacent dimensions; GPT-NeoX and Llama pair the first half with the second half (rotate_half). Weights trained with one convention give garbage with the other.

Llama 3 uses base \(b = 500{,}000\) from the start and extends context in a final stage; Code Llama raised the base to 1,000,000 for 100k-token contexts. Extension still needs some long-sequence fine-tuning, and a model claiming 128k may use the far end poorly.

positions.py
import torch

def sinusoidal(T, d):
    pos = torch.arange(T).unsqueeze(1)                       # (T, 1)
    freq = 10000 ** (-torch.arange(0, d, 2) / d)             # (d/2,)
    pe = torch.zeros(T, d)
    pe[:, 0::2] = torch.sin(pos * freq)
    pe[:, 1::2] = torch.cos(pos * freq)
    return pe                                                # (T, d)

def rope(x, pos, base=10000.0):
    # x: (..., d) with d even; pairs are (0, d/2), (1, d/2+1), ... as in Llama
    d = x.shape[-1]
    theta = base ** (-torch.arange(0, d, 2, dtype=torch.float32) / d)   # (d/2,)
    ang = pos * theta                                                   # (d/2,)
    cos, sin = torch.cos(ang).repeat(2), torch.sin(ang).repeat(2)       # (d,)
    x1, x2 = x[..., : d // 2], x[..., d // 2 :]
    rotated_half = torch.cat([-x2, x1], dim=-1)
    return x * cos + rotated_half * sin

print(sinusoidal(6, 8).round(decimals=2))

torch.manual_seed(0)
q, k = torch.randn(64), torch.randn(64)
# Same offset (3) at very different absolute positions gives the same score.
s1 = rope(q, 10) @ rope(k, 7)
s2 = rope(q, 1010) @ rope(k, 1007)
print(s1.item(), s2.item())                 # equal up to float error
print((rope(q, 10).norm() - q.norm()).item())  # ~0: rotation keeps length
Common confusions

  • RoPE is added to the embeddings like sinusoidal encoding.

    RoPE is applied inside every attention layer, to queries and keys only. Nothing is added to the residual stream.

  • Relative position encoding means the model cannot tell absolute position.

    It mostly cannot directly, but the causal mask and the start-of-sequence token give anchors; in practice this has not been a problem.

  • Context extension is free.

    PI and YaRN need at least some long-sequence fine-tuning, and a 128k model may still use the far end poorly.

  • Longer context only needs a position fix.

    Attention compute and KV cache memory also grow with length (section 05).

  • Sinusoidal encoding extrapolates to any length.

    It yields valid vectors at any position, but models trained with it still degrade past their training length.

Check yourself

  1. Why do transformers need positional information while RNNs do not?

    Show answer

    An RNN processes tokens in order, so order is built in. Attention treats inputs as an unordered set; shuffling inputs only shuffles outputs.

  2. Why can't GPT-2 process a sequence of 2000 tokens without modification?

    Show answer

    It uses a learned absolute position table with exactly 1024 rows; there is no vector for positions 1024 and beyond.

  3. In RoPE, which of \(Q\), \(K\), \(V\) are rotated, and why does the score depend only on \(m-n\)?

    Show answer

    \(Q\) and \(K\). Rotating q by \(m\theta\) and k by \(n\theta\) and taking a dot product equals rotating by the difference \((m-n)\theta\), because rotations compose and the dot product sees only the relative angle.

  4. Position Interpolation extends a 4k model to 16k. What position value is used for the token at index 12,000?

    Show answer

    \(12{,}000/4 = 3{,}000\) (scale factor \(s = 16\text{k}/4\text{k} = 4\)).

  5. What problem with Position Interpolation do NTK-aware scaling and YaRN address?

    Show answer

    PI compresses all frequencies equally, blurring the high-frequency dimensions that encode fine local order. NTK-aware and YaRN interpolate mostly the low-frequency dimensions and leave the high-frequency ones nearly intact.

05Attention

Attention is a soft lookup: queries match keys, values flow back

After the embedding every token knows its identity and position, but nothing about its neighbours. In "The animal didn't cross the street because it was too tired", the vector for " it" needs information from " animal". Attention moves information between positions.

attention.py
import math
import torch
import torch.nn.functional as F

torch.manual_seed(0)
B, h, T, dk = 2, 4, 5, 16
q, k, v = (torch.randn(B, h, T, dk) for _ in range(3))

scores = q @ k.transpose(-2, -1) / math.sqrt(dk)         # (B, h, T, T)
causal = torch.tril(torch.ones(T, T, dtype=torch.bool))
scores = scores.masked_fill(~causal, float("-inf"))
weights = scores.softmax(dim=-1)                         # each row sums to 1
out = weights @ v                                        # (B, h, T, dk)

ref = F.scaled_dot_product_attention(q, k, v, is_causal=True)
print(torch.allclose(out, ref, atol=1e-6))               # True
print(weights[0, 0].round(decimals=2))                   # lower-triangular pattern

# Why sqrt(dk): unscaled scores have std ~ sqrt(dk)
a, b = torch.randn(10000, 128), torch.randn(10000, 128)
print((a * b).sum(-1).std().item(), math.sqrt(128))

# GQA: 8 query heads share 2 KV heads by repeating each KV head 4 times
qg = torch.randn(1, 8, T, dk)
kg, vg = torch.randn(1, 2, T, dk), torch.randn(1, 2, T, dk)
kg, vg = kg.repeat_interleave(4, dim=1), vg.repeat_interleave(4, dim=1)
print(F.scaled_dot_product_attention(qg, kg, vg, is_causal=True).shape)  # (1, 8, 5, 16)
Common confusions

  • Q, K and V are different inputs.

    In self-attention they are three linear projections of the same input \(X\).

  • Attention weights tell you what the model thinks is important.

    They show where information was read from in one head of one layer. Interpreting them requires care (section 06).

  • The causal mask is only needed in training.

    It is needed in any multi-token forward pass, including prefill. During cached decode the single new query only sees past keys anyway.

  • FlashAttention is an approximation.

    It is exact; it reorders the computation to cut memory traffic.

  • Multi-head attention costs \(h\) times more.

    Each head has width \(d_{\text{model}}/h\), so total cost is about that of one full-width head.

  • The KV cache stores queries too.

    Past queries are never needed again, only past keys and values.

Check yourself

  1. Write the shapes of \(Q\), \(K^\top\), \(QK^\top\) and the output for one head with \(T = 10\), \(d_k = 64\).

    Show answer

    \(Q\): (10, 64), \(K^\top\): (64, 10), \(QK^\top\): (10, 10), output: (10, 64).

  2. If \(d_k = 256\) and you forget the \(\sqrt{d_k}\) scaling, what happens?

    Show answer

    Scores have standard deviation around 16, softmax becomes nearly one-hot, its gradients vanish, and training is slow or unstable.

  3. Why can the KV cache reuse keys and values without recomputing them?

    Show answer

    With causal masking, a past token's representation at every layer depends only on tokens at or before it, so appending tokens never changes it.

  4. A model has 40 layers, 8 KV heads, \(d_k = 128\), fp16. How much KV cache does one 32k-token sequence need?

    Show answer

    \(2 \times 40 \times 8 \times 128 \times 32{,}768 \times 2 = 5{,}368{,}709{,}120\) bytes, about 5.4 GB (5 GiB).

  5. Does FlashAttention change the asymptotic FLOP count? What does it change?

    Show answer

    No, still \(O(n^2 d)\). It cuts memory from \(O(n^2)\) to \(O(n)\) and slow HBM reads and writes, so it is much faster in wall-clock time.

06Layers of Understanding

Each block adds an update to a shared residual stream

A block combines attention and the MLP, each wrapped in a normalization and a residual connection. A model is a stack of \(N\) such blocks (12 in GPT-2 small, 80 in Llama 3 70B), then a final norm and the unembedding.

Why this structure matters. Gradients: the derivative of \(x + f(x)\) has an identity term, so the loss reaches early layers directly, which makes 100-layer networks trainable. Communication: a layer can write into a subspace that a much later layer reads. Default behaviour: a fresh block adds roughly nothing, so the network starts near embedding-straight-to-unembedding and learns refinements.

Geva et al. (2021) read the MLP as a key-value memory: each hidden neuron has an input pattern (a column of \(W_1\), the key) and an output pattern (a row of \(W_2\), the value). When the stream matches the key, the neuron adds its value. Edits to factual associations are largely found in mid-layer MLPs.

  • Circuits: heads and neurons implementing an identifiable algorithm (Anthropic, "A Mathematical Framework for Transformer Circuits", 2021).
  • Superposition: models pack more features than dimensions into nearly orthogonal directions, so single neurons are often polysemantic.
  • Sparse autoencoders: decompose activations into many interpretable features, scaled to production models in "Scaling Monosemanticity" (2024).
  • Tuned lens (Belrose et al., 2023): a small linear map per layer fixes the logit lens on model families where it works poorly.
blocks_and_lens.py
import torch
import torch.nn as nn
import torch.nn.functional as F

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.eps, self.weight = eps, nn.Parameter(torch.ones(d))
    def forward(self, x):
        return self.weight * x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

class SwiGLU(nn.Module):
    def __init__(self, d, d_ff):
        super().__init__()
        self.gate = nn.Linear(d, d_ff, bias=False)
        self.up = nn.Linear(d, d_ff, bias=False)
        self.down = nn.Linear(d_ff, d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))

class LlamaStyleBlock(nn.Module):
    def __init__(self, d=256, n_head=4):
        super().__init__()
        self.n1, self.n2 = RMSNorm(d), RMSNorm(d)
        self.attn = nn.MultiheadAttention(d, n_head, bias=False, batch_first=True)
        self.mlp = SwiGLU(d, int(8 * d / 3))
    def forward(self, x):
        T = x.shape[1]
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)  # True = blocked
        h = self.n1(x)
        x = x + self.attn(h, h, h, attn_mask=mask, need_weights=False)[0]
        return x + self.mlp(self.n2(x))

print(LlamaStyleBlock()(torch.randn(2, 10, 256)).shape)   # (2, 10, 256)

for layer, h in enumerate(out.hidden_states):         # embeddings + 12 blocks

    h_last = h[0, -1] if layer == len(out.hidden_states) - 1 else model.transformer.ln_f(h[0, -1])
    top = model.lm_head(h_last).topk(3).indices
    print(layer, [tok.decode(t) for t in top])

The block uses PyTorch's nn.MultiheadAttention and no RoPE to stay short; section 07 writes attention by hand. In the logit-lens output, early layers predict generic continuations and " Paris" should appear only in later layers.

Common confusions

  • Each layer replaces the representation.

    Each layer adds an update to the residual stream; the original embedding is still in there, summed with everything else.

  • LayerNorm normalizes over the batch.

    It normalizes each token's feature vector alone, which is why it works the same at batch size 1.

  • Pre-norm and post-norm are cosmetic.

    Where the norm sits decides whether the residual path is a clean identity, which strongly affects trainability of deep models.

  • The MLP is the less important part.

    It holds about two thirds of the parameters and much of the factual knowledge.

  • Neuron 1234 means "cat".

    Because of superposition, most neurons respond to several unrelated features; meaningful units are usually directions, not single neurons.

  • The logit lens shows what the model is thinking.

    It shows what the final unembedding would read from a state never trained to be read that way. A useful but biased probe.

Check yourself

  1. Write the two equations of a pre-norm transformer block.

    Show answer

    \(x' = x + \text{Attn}(\text{Norm}_1(x))\) and \(x'' = x' + \text{MLP}(\text{Norm}_2(x'))\).

  2. What does RMSNorm drop compared with LayerNorm, and why is that acceptable?

    Show answer

    The mean subtraction and the learned bias \(\beta\). Empirically, re-centering contributes little; rescaling stabilizes training, and the simpler version is faster.

  3. Why do pre-norm models need a final normalization before the unembedding?

    Show answer

    The stream itself is never normalized (only copies fed to sub-layers), so its scale can grow through the layers; ln_f rescales it before scoring against the vocabulary.

  4. A SwiGLU MLP with \(d_{\text{model}} = 4096\) uses \(d_{\text{ff}} = 11008\) (Llama 2 7B). How many parameters (no biases)? Compare with a GELU MLP with \(d_{\text{ff}} = 4 \times 4096\).

    Show answer

    SwiGLU: \(3 \times 4096 \times 11008 = 135{,}266{,}304 \approx 135\)M. GELU: \(2 \times 4096 \times 16384 = 134{,}217{,}728 \approx 134\)M. Nearly identical, by design.

  5. What does the logit lens rely on to make sense at all?

    Show answer

    The residual stream: every layer reads from and writes to the same vector space, so intermediate states are roughly in the format the unembedding expects.

07GPT-2 from Scratch

GPT-2 is about 150 lines, and it must match OpenAI's logits

You now write GPT-2 yourself from sections 01 to 06, prove it correct by loading OpenAI's released weights and matching Hugging Face's logits, then add sampling and train a small version from scratch. Save the model as gpt2.py; later snippets import from it.

In terms of earlier sections, GPT-2 is: byte-level BPE (02), tied embeddings (03), learned absolute positions (04), multi-head causal attention with \(d_k = 64\) (05), and pre-norm blocks with LayerNorm and a GELU MLP of width \(4\times\) n_embd (06).

  • Names match Hugging Face (transformer.wte, h.0.attn.c_attn, ln_f) so the pretrained state_dict copies key by key.
  • c_attn computes Q, K and V in one matmul of shape (768, 2304), then splits.
  • Attention is written by hand. The four lines from att = ... to y = att @ v can be replaced by F.scaled_dot_product_attention(q, k, v, is_causal=True).
  • Initialization: normal with std 0.02; each residual branch's output projection is scaled by \(1/\sqrt{2N}\), since there are \(2N\) additions into the stream.
  • forward returns logits for every position and, with targets, the cross-entropy averaged over all B x T positions.
gpt2.py
import math
from dataclasses import dataclass

import torch
import torch.nn as nn
import torch.nn.functional as F


@dataclass
class GPTConfig:
    block_size: int = 1024   # max context length (number of learned positions)
    vocab_size: int = 50257  # GPT-2 BPE vocabulary
    n_layer: int = 12
    n_head: int = 12
    n_embd: int = 768
    dropout: float = 0.0


class CausalSelfAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        assert cfg.n_embd % cfg.n_head == 0
        # One matmul produces Q, K and V together; it is faster than three and
        # matches the layout of OpenAI's checkpoint.
        self.c_attn = nn.Linear(cfg.n_embd, 3 * cfg.n_embd)
        self.c_proj = nn.Linear(cfg.n_embd, cfg.n_embd)
        self.c_proj.SCALE_INIT = True
        self.n_head = cfg.n_head
        self.drop = nn.Dropout(cfg.dropout)
        # Not a parameter and not saved: HF checkpoints do not contain it.
        mask = torch.tril(torch.ones(cfg.block_size, cfg.block_size))
        self.register_buffer("mask", mask.view(1, 1, cfg.block_size, cfg.block_size), persistent=False)

    def forward(self, x):
        B, T, C = x.shape
        hd = C // self.n_head
        q, k, v = self.c_attn(x).split(C, dim=2)
        # (B, T, C) -> (B, n_head, T, hd) so every head attends independently.
        q = q.view(B, T, self.n_head, hd).transpose(1, 2)
        k = k.view(B, T, self.n_head, hd).transpose(1, 2)
        v = v.view(B, T, self.n_head, hd).transpose(1, 2)
        att = (q @ k.transpose(-2, -1)) / math.sqrt(hd)           # (B, nh, T, T)
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
        att = self.drop(F.softmax(att, dim=-1))
        y = att @ v                                               # (B, nh, T, hd)
        y = y.transpose(1, 2).contiguous().view(B, T, C)          # re-merge heads
        return self.drop(self.c_proj(y))


class MLP(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.c_fc = nn.Linear(cfg.n_embd, 4 * cfg.n_embd)
        self.c_proj = nn.Linear(4 * cfg.n_embd, cfg.n_embd)
        self.c_proj.SCALE_INIT = True
        self.drop = nn.Dropout(cfg.dropout)

    def forward(self, x):
        # GPT-2 was trained with the tanh approximation; exact GELU would
        # slightly change the outputs of the pretrained weights.
        return self.drop(self.c_proj(F.gelu(self.c_fc(x), approximate="tanh")))


class Block(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.ln_1 = nn.LayerNorm(cfg.n_embd)
        self.attn = CausalSelfAttention(cfg)
        self.ln_2 = nn.LayerNorm(cfg.n_embd)
        self.mlp = MLP(cfg)

    def forward(self, x):
        # Pre-norm: the residual stream x itself is never normalized, which
        # keeps a clean gradient path from the loss to the embeddings.
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x


class GPT(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg = cfg
        # Names mirror Hugging Face's GPT2LMHeadModel so weights load by key.
        self.transformer = nn.ModuleDict(dict(
            wte=nn.Embedding(cfg.vocab_size, cfg.n_embd),
            wpe=nn.Embedding(cfg.block_size, cfg.n_embd),
            drop=nn.Dropout(cfg.dropout),
            h=nn.ModuleList([Block(cfg) for _ in range(cfg.n_layer)]),
            ln_f=nn.LayerNorm(cfg.n_embd),
        ))
        self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        self.lm_head.weight = self.transformer.wte.weight  # weight tying
        self.apply(self._init_weights)

    def _init_weights(self, m):
        if isinstance(m, nn.Linear):
            std = 0.02
            if getattr(m, "SCALE_INIT", False):
                # Each block adds two outputs into the residual stream; scaling
                # keeps the stream's variance from growing with depth.
                std *= (2 * self.cfg.n_layer) ** -0.5
            nn.init.normal_(m.weight, mean=0.0, std=std)
            if m.bias is not None:
                nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        assert T <= self.cfg.block_size, "sequence longer than block_size"
        pos = torch.arange(T, device=idx.device)
        x = self.transformer.wte(idx) + self.transformer.wpe(pos)  # (B, T, C)
        x = self.transformer.drop(x)
        for block in self.transformer.h:
            x = block(x)
        logits = self.lm_head(self.transformer.ln_f(x))            # (B, T, vocab)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

    @classmethod
    def from_pretrained(cls, name="gpt2"):
        from transformers import GPT2LMHeadModel
        sizes = {
            "gpt2": dict(n_layer=12, n_head=12, n_embd=768),
            "gpt2-medium": dict(n_layer=24, n_head=16, n_embd=1024),
            "gpt2-large": dict(n_layer=36, n_head=20, n_embd=1280),
            "gpt2-xl": dict(n_layer=48, n_head=25, n_embd=1600),
        }
        model = cls(GPTConfig(**sizes[name]))
        sd = model.state_dict()
        sd_hf = GPT2LMHeadModel.from_pretrained(name).state_dict()
        # OpenAI stored these as Conv1D, i.e. (in, out); nn.Linear wants (out, in).
        transposed = ("attn.c_attn.weight", "attn.c_proj.weight", "mlp.c_fc.weight", "mlp.c_proj.weight")
        for k, v in sd_hf.items():
            if k.endswith((".attn.bias", ".attn.masked_bias")):
                continue  # HF's own causal-mask buffers, not weights
            src = v.t() if k.endswith(transposed) else v
            assert sd[k].shape == src.shape, k
            with torch.no_grad():
                sd[k].copy_(src)
        return model

    @torch.no_grad()
    def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None, top_p=None):
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -self.cfg.block_size:]
            logits, _ = self(idx_cond)
            logits = logits[:, -1, :] / max(temperature, 1e-5)
            if top_k is not None:
                kth = torch.topk(logits, min(top_k, logits.size(-1))).values[:, [-1]]
                logits[logits < kth] = float("-inf")
            if top_p is not None:
                sorted_logits, sorted_idx = torch.sort(logits, descending=True)
                probs = F.softmax(sorted_logits, dim=-1)
                # Drop a token if the tokens ranked above it already cover top_p,
                # so the most likely token always survives.
                drop = probs.cumsum(dim=-1) - probs > top_p
                sorted_logits[drop] = float("-inf")
                logits = torch.full_like(logits, float("-inf")).scatter(1, sorted_idx, sorted_logits)
            probs = F.softmax(logits, dim=-1)
            next_id = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, next_id], dim=1)
        return idx

If the maximum difference is large, the usual culprits are a missing transpose, exact GELU instead of approximate="tanh", a forgotten final ln_f, or the mask not being applied. Differences around \(10^{-5}\) to \(10^{-4}\) are float noise; 0.1 or more is a bug.

In generate the order is: crop the context to block_size, take the last position's logits, apply temperature, then top-k, then top-p, then sample with torch.multinomial. It recomputes the whole context every step: there is no KV cache. Adding one is part of the chapter project.

import os
import urllib.request

import torch

from gpt2 import GPT, GPTConfig

url = "https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt"
if not os.path.exists("input.txt"):
    urllib.request.urlretrieve(url, "input.txt")
text = open("input.txt").read()

# Character-level keeps the vocab at ~65, so a tiny model learns fast on a CPU.
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}
encode = lambda s: [stoi[c] for c in s]
decode = lambda ids: "".join(chars[i] for i in ids)

data = torch.tensor(encode(text))
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]

device = "cuda" if torch.cuda.is_available() else ("mps" if torch.backends.mps.is_available() else "cpu")
cfg = GPTConfig(block_size=128, vocab_size=len(chars), n_layer=4, n_head=4, n_embd=128, dropout=0.1)
model = GPT(cfg).to(device)
print(f"{sum(p.numel() for p in model.parameters()) / 1e6:.2f}M parameters on {device}")

def get_batch(split, B=32):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - cfg.block_size - 1, (B,))
    x = torch.stack([d[i : i + cfg.block_size] for i in ix])
    y = torch.stack([d[i + 1 : i + 1 + cfg.block_size] for i in ix])  # shifted by one: next-token targets
    return x.to(device), y.to(device)

@torch.no_grad()
def estimate_loss(iters=20):
    model.eval()
    out = {}
    for split in ("train", "val"):
        out[split] = sum(model(*get_batch(split))[1].item() for _ in range(iters)) / iters
    model.train()
    return out

opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.1)
max_steps = int(os.environ.get("STEPS", 2000))
for step in range(max_steps + 1):
    if step % 250 == 0:
        losses = estimate_loss()
        print(f"step {step}: train {losses['train']:.3f}, val {losses['val']:.3f}")
    x, y = get_batch("train")
    _, loss = model(x, y)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    # Clipping guards against the occasional huge gradient early in training.
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()

model.eval()
start = torch.tensor([encode("ROMEO:")], device=device)
print(decode(model.generate(start, 300, temperature=0.8, top_k=20)[0].tolist()))

Common confusions

  • Temperature changes what the model knows.

    It only reshapes the output distribution at sampling time; the logits are unchanged.

  • Top-k and top-p are alternatives you must choose between.

    They compose; many APIs apply both, and temperature is applied before either.

  • Matching Hugging Face's logits exactly to 0 is required.

    Different operation orders give tiny float differences (around \(10^{-5}\) to \(10^{-4}\)). Differences of 0.1 or more mean a real bug.

  • Training loss going down means the model is getting better.

    Watch validation loss. If train loss falls while validation loss rises, the model is memorizing.

  • The trained character model is a small GPT-2.

    Same architecture, different tokenizer and far fewer parameters; it cannot use GPT-2's weights because vocabulary and sizes differ.

Check yourself

  1. Why does from_pretrained transpose some weights but not others (for example not wte or the LayerNorm weights)?

    Show answer

    Only the four linear layers stored as Conv1D in the original checkpoint have (in, out) layout; embeddings and LayerNorm parameters are stored the same way in both implementations.

  2. What is the expected initial loss of the character model, and why?

    Show answer

    About \(\ln 65 \approx 4.17\): at random initialization the output is close to uniform over 65 characters, and the cross-entropy of a uniform guess is \(\ln V\).

  3. With \(\tau = 0.5\), how does the probability ratio between tokens with logits 2.0 and 1.0 change versus \(\tau = 1\)?

    Show answer

    At \(\tau = 1\) the ratio is \(e \approx 2.7\). At \(\tau = 0.5\) it is \(e^2 \approx 7.4\): the likelier token becomes relatively likelier.

  4. Why does the top-p implementation subtract each token's own probability before comparing the cumulative sum with \(p\)?

    Show answer

    So the token that crosses the threshold is kept, and the top token always survives even if it alone exceeds \(p\).

  5. Name two changes that would make generate much faster for long outputs.

    Show answer

    A KV cache (compute only the new token's \(q, k, v\) each step) and F.scaled_dot_product_attention (fused FlashAttention kernels). Half precision on a GPU and batching also help.
